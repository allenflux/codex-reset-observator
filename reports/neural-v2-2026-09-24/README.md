## 采集快照上的时点回放

为与现用模型作公平比较，冻结 v1 权重，只评估它训练完成之后的预测起点。每个 UTC 日取首个成功采集时刻，每次重训仅使用当时已经采集到的历史，且训练标签必须在该时刻前成熟。固定 v1、每日重训流程及两个基线共享同一批预测输入和目标。

窗口为 9 月 12 日 02:43 UTC 至 9 月 22 日 00:04 UTC，共 **11 个成熟日样本**；24h 正例 2 个、48h 正例 3 个，另有 2 个尚未满 48 小时的起点被排除。所有目标按窗口满 48 小时后的首个可用快照冻结，后续修订不静默改写标签。

| 方案 | 24h Brier | 48h Brier | 平均 Brier ↓ |
| --- | ---: | ---: | ---: |
| 固定现用 v1 | 0.161371 | 0.250000 | 0.205686 |
| 每日重新训练同一网络 | 0.171294 | 0.297275 | 0.234284 |
| 每日更新历史频率 | 0.158746 | 0.246220 | 0.202483 |
| 每日更新 Poisson 频率 | 0.151438 | 0.219231 | **0.185335** |

这评估的是**每日重训流程**，不是 9 月 24 日才训练完成的最终 v2 权重。最终 v2 没有新的前瞻结果；把它套回已参与拟合的这 11 天会泄漏目标。

11 个样本过少，48 小时目标也相互重叠，不作显著性或稳定优劣结论。这些起点都存在后续来源修订警告；回放保持原时点标签，但来源完整性和执行时间的准确性仍未被独立核实。较早的每次训练历史本身仍是回顾性补录。本次保留 v1 是谨慎的版本选择，不代表 v1 已可靠胜过简单基线。

## 本地复现与后续训练

环境：Python 3.12.11、scikit-learn 1.9.1、NumPy 2.5.3，依赖由 `uv.lock` 固定。在项目根目录执行；已有 `.env` 中的 MySQL 配置继续使用，训练在本机完成。

使用本次冻结的本地文件，可重复训练候选和回放：

```bash
uv run --extra ml observatory train \
  --history var/training/2026-09-24-v2/training-history.json \
  --observed-until 2026-09-24T00:46:51.683292+00:00 \
  --model-version reset-mlp-8-tanh-v2 \
  --model var/training/2026-09-24-v2/reproduced-model.json \
  --report var/training/2026-09-24-v2/reproduced-evaluation.json

uv run --extra ml python -m observatory.retraining \
  --snapshot var/training/2026-09-24-v2/mysql-snapshot.json \
  --incumbent var/training/2026-09-24-v2/incumbent-v1.json \
  --output var/training/2026-09-24-v2/reproduced-comparison.json
```

上述冻结文件仅存在本地；新克隆仓库应使用 README 中的 [MySQL 本地训练与对照命令](../../README.md#本地训练与前瞻评估)。数据库继续增长时，应给下一次实验使用新的目录并记录新截止时间；不要覆盖本次实验文件，也不要把原始采集数据提交到仓库。
